# targets runs on shared machines

The general rules -- where heavy work may run, why only a `systemd-run` unit survives
memory pressure, never signalling what you did not start, syncing nodes -- are in
`hpc-cluster-runs` in `r-project-core`. This skill adds what is specific to `targets`.

## What is light, and what is not

Light enough for a control node: `tar_progress()`, `tar_manifest()`, `tar_meta()`,
`tar_outdated()`, `tar_validate()`, and `tar_read()` of small objects.

Heavy: `tar_make()` on anything real, including `tar_make(callr_function = NULL)` on
a single real target.

## Launching

```sh
pgrep -af "tar_make"                  ## preflight: is a run already live?
systemd-run --user --unit=<name> --collect \
  --working-directory="$PWD" bash _tmp/run_<name>.sh
```

```bash
{ echo "=== <name> launch $(date -Is) ==="
  Rscript-4.6.1 -e 'targets::tar_make(callr_function = NULL)'
  echo "=== EXIT=$? $(date -Is) ==="
} > "$LOG" 2>&1
```

`callr_function = NULL` because the outer callr wrapper crashes under heavy
optimiser and container load.

**One store cannot host two concurrent `tar_make()` calls.** On NFS, a *refused*
second `tar_make()` still compacts and replaces `_targets/meta/meta` before refusing,
orphaning the running pipeline's open handle. Check for a live run and launch in a
single command, never as two steps someone else can interleave.

## Stopping -- order matters

**Launched as a systemd unit:** `systemctl --user stop <name>` signals the whole
cgroup, including the `callr` child. Then confirm nothing survived and clear the
lock if it remains:

```sh
ps -u "$USER" -o pid,etime,cmd | grep -E 'callr|exec/R' | grep -v grep
Rscript-4.6.1 -e 'targets::tar_unblock_process(store = "_targets")'
```

**Launched under `screen`:** ending the screen does **not** stop the run.
`tar_make()` wraps the pipeline in a `callr` child that does not receive SIGHUP; it
survives and keeps holding the store lock.

```sh
## 1. kill any retry loop FIRST, or it treats the dead R process as a crash
##    and relaunches everything
## 2. end the screen (the callr child survives this)
screen -X -S <name> quit
## 3. find and kill the surviving callr child
ps -u "$USER" -o pid,etime,cmd | grep -E 'callr|exec/R' | grep -v grep
kill -TERM <pid>
## 4. release the store lock
Rscript-4.6.1 -e 'targets::tar_unblock_process(store = "_targets")'
```

Then reap containers on every compute host, workers before containers -- neither
SSH nor crew reaps a worker's container children, and orphaned PSOCK workers restart
them.

## Worker checkouts and tracked files

**`deployment = "main"` for any target that writes a git-tracked path** --
`README.md`, `INFO.md`, `reports/pdf/*`, `citations/*.bib`, an input manifest.
Otherwise a worker writes it inside that worker's checkout, dirties the tree, and
blocks the next `git merge --ff-only` node sync.

## A store on shared storage

- **A `format = "file"` target whose file lives in a host-local directory** makes a
  shared store reference a file that exists on one machine. `tar_outdated()` from any
  other host then reports that target and its entire downstream cone as outdated. That
  is survivable only if the file is regenerated byte-identically, so hashes match and
  nothing downstream reruns.
- Workers read settings from `.Rprofile`, never from `_local.R` -- see
  `targets-project-setup`.

## Controller sizing

- `_hosts.R` is sourced **before** `tar_option_set()`, so its `crew.ssh.*` options
  drive the controller construction.
- Size the local fallback pool so all branches run in one wave, and cap per-process
  memory fractions for the worker count. Scope such a cap to the stage that needs
  it: a runtime resource knob inside a target's command is hashed, and retuning it
  invalidates cached work.
- Raise `crashes_max` when running many workers; the default trips on a race.
- Size per-node worker caps to the heaviest stage that will use the pool, and keep a
  node running another project's long run out of the pool.
